# Informe Maestro - Sistema de Gestion de Planificacion Estrategica

## 1. Resumen ejecutivo

Se realizo un analisis documental de la carpeta de trabajo del OTEC con el objetivo de definir las bases para construir un sistema de gestion de planificacion estrategica alineado con el Sistema de Gestion de Calidad.

La conclusion principal es que el sistema requerido no debe limitarse a un tablero de indicadores. Debe operar como una plataforma integral de planificacion, seguimiento, evidencia, control documental y mejora continua, capaz de soportar auditorias, revision por la direccion y control de cumplimiento.

## 3. Hallazgos del analisis de negocio

El marco documental revisado muestra que la planificacion estrategica del OTEC es un componente rector del SGC y se vincula directamente con:

- objetivos de calidad
- indicadores de gestion
- seguimiento de cursos y encuestas
- revision por la direccion
- acciones correctivas y preventivas
- reclamos y no conformidades
- control documental y registros
- proyeccion financiera y flujo de caja

Necesidades detectadas:

- centralizar informacion hoy dispersa
- asegurar trazabilidad entre objetivo, resultado, evidencia y accion
- controlar vigencia documental
- facilitar auditorias y fiscalizaciones
- mejorar visibilidad ejecutiva del plan

## 4. Vision del sistema propuesto

El sistema debe ser una plataforma web interna que permita:

- planificar el periodo estrategico anual
- definir objetivos, metas e indicadores
- registrar y analizar resultados
- consolidar revision por la direccion
- gestionar AC/AP
- administrar reclamos y no conformidades
- controlar documentos y registros
- mantener evidencias y bitacora de auditoria
- emitir reportes ejecutivos y auditables

## 9. Reglas de negocio criticas

- un solo plan vigente por ano
- no aprobar plan sin objetivos, indicadores y responsables
- toda revision por la direccion debe tener entradas obligatorias y acuerdos con plazo
- toda AC/AP debe tener origen, responsable y verificacion de eficacia
- toda nueva revision documental debe obsoletar la anterior
- los registros deben poder conservarse por al menos 3 anos

## 10. Requisitos no funcionales clave

- sistema web responsivo
- control de acceso por roles
- bitacora auditable inalterable
- almacenamiento de adjuntos
- exportacion a PDF y Excel
- historico multianual
- trazabilidad transversal

## 15. Riesgos relevantes

- ampliar alcance sin control
- no validar con usuarios clave
- construir solo un tablero sin soporte de cumplimiento
- baja calidad de datos historicos
- mantener planillas paralelas tras la salida

## 16. Recomendaciones finales

- usar el paquete generado como base oficial del proyecto
- validar internamente el alcance MVP antes de solicitar propuestas
- exigir analisis detallado y demos iterativas al proveedor
- nombrar un duenio funcional del sistema
- planificar capacitacion y adopcion desde el inicio
